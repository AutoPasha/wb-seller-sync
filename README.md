# wb-seller-sync

Read-only коннектор Wildberries Seller API: карточки, остатки, заказы, продажи и
отчёт о реализации складываются в SQLite-снимок, из которого их читает всё
остальное.

Записать что-либо в кабинет продавца коннектор не может. Это не обещание в
README, а свойство конструкции: транспорт принимает не URL, а имя метода из
реестра, и пишущих методов в реестре нет.

```
$ wb-sync registry
Разрешённые методы (всё остальное транспорт отклоняет до отправки):

  seller_info    GET  https://common-api.wildberries.ru/api/v1/seller-info
                 источник сигнатуры: документация
  cards_list     POST https://content-api.wildberries.ru/content/v2/get/cards/list
                 источник сигнатуры: практика, требует проверки
  stocks         GET  https://statistics-api.wildberries.ru/api/v1/supplier/stocks
                 источник сигнатуры: документация
  ...

Пишущих методов в реестре: 0. Глаголы, доступные транспорту: GET, POST.
```

## Зачем он такой

Выгрузка данных с Wildberries — редкий случай, когда сложность не в коде, а в
поведении источника. Каждая из вещей ниже ломает наивную реализацию **молча**:
процесс не падает, в логах чисто, а цифры в отчёте неверные.

**Тип токена решает, поедет ли синхронизация вообще.** С 30 марта 2026 у WB
четыре типа токенов, и у базовых лимиты снижены вплоть до одного запроса в
3–24 часа. Регулярная выгрузка на таком токене невозможна, но выглядит это не
как отказ, а как «ваша интеграция тормозит». Поэтому `wb-sync token`
показывает срок жизни, контур и — через `/ping` по всем тринадцати доменам —
какие категории токену действительно разрешены. А 429 с многочасовой паузой
коннектор не ретраит, а объясняет: ретраи здесь не лечат, нужен другой токен.

**У токена нет refresh.** Живёт до 180 дней, обновляется руками в кабинете и
умирает без предупреждения. Срок читается из самого токена заранее, чтобы
показать его рядом со статусом магазина, а не узнать постфактум по пустым
витринам.

**Курсор `lastChangeDate` умеет застревать.** Если у всей страницы одинаковая
метка времени — а так бывает при массовой перезаливке остатков — следующий
запрос вернёт ту же страницу. Бесконечно. Коннектор это распознаёт и
останавливается с внятным сообщением; `--nudge` включает сдвиг курсора на
миллисекунду, но тогда в отчёте о выгрузке появляется честное предупреждение,
что строки с той же меткой могли не попасть.

**`rrd_id` в отчёте о реализации нельзя брать из последней строки.** Порядок
строк в ответе не гарантирован, курсор откатывается назад, страницы приезжают
повторно — и в финансовой витрине появляются задвоенные суммы, которые потом
ищут вручную. Берётся максимум по всей странице.

**Отчёт о реализации меняется задним числом.** Он появляется через 2–4 дня
после конца недели и ещё 7–14 дней перегенерируется: строки добавляются,
суммы уточняются, возвраты переезжают. Поэтому окно в 42 дня перечитывается
целиком при каждом запуске. Из этого же следует практический вывод для
приёмки: сверять цифры с кабинетом имеет смысл только по закрытым периодам —
по незакрытым расходятся не расчёты, а сам источник.

**WB добавляет поля в ответы без анонса.** Строка сохраняется целиком в JSON
рядом с разобранными ключевыми полями: новое поле оказывается в базе сразу и
достаётся задним числом, без повторной выгрузки истории.

**Лимиты считаются по доменам раздельно.** Упереться в минутный потолок
статистики и из-за этого притормозить выгрузку карточек — обидно и незачем,
поэтому у каждого домена свой бакет.

## Установка

```bash
pip install -e ".[dev]"
```

Python 3.11+, из зависимостей только `requests`.

## Работа

Токен берётся из окружения и никогда не принимается аргументом командной
строки: аргументы видны в истории оболочки и в списке процессов.

```bash
export WB_TOKEN_1="eyJhbGciOi..."

wb-sync token                      # срок, контур, доступные категории
wb-sync token --offline            # только разбор токена, без обращения к WB
wb-sync --store 1 pull cards
wb-sync --store 1 pull stocks --days 1
wb-sync --store 1 pull orders --since 2026-07-01
wb-sync --store 1 pull realization --window 42
wb-sync --store 1 status
```

Несколько магазинов — `WB_TOKEN_2`, `WB_TOKEN_3` и так далее; данные в снимке
разделены по `store_id`.

Прогон публикуется атомарно: либо весь целиком, либо никак. Отчёт, построенный
по половине выгруженных остатков, выглядит правдоподобно — и врёт.

## Проверки

```bash
pytest
```

45 тестов, ни одного обращения в сеть: WB подменяется очередью ответов, часы и
паузы — счётчиками, поэтому тест на минутный лимит статистики идёт
миллисекунды. Каждая грабля из списка выше закрыта отдельным тестом, который
воспроизводит именно её.

## Что проверено, а что нет

Разделение принципиальное, поэтому оно и в коде: у каждого метода в реестре
стоит `source`, а `wb-sync registry` его печатает.

| Проверено | Как |
|---|---|
| Хосты всех 13 категорий | живые запросы, все домены отвечают |
| `stocks`, `orders`, `sales`: пути, `dateFrom`, `flag`, курсор по `lastChangeDate`, потолок ~80 000 строк | дословно по документации WB |
| `/ping` как способ узнать доступные категории | документация: метод проверяет совпадение категории токена и сервиса |
| Лимиты: статистика 1/мин, контент 100/мин, продвижение 5/сек, отзывы 3/сек, ping 3/30 сек | документация |
| Типы токенов и их влияние на лимиты | анонс WB от 30.03.2026 |

| Не проверено на живом токене | Почему |
|---|---|
| `content/v2/get/cards/list` — форма курсора | доступа к боевому кабинету не было; сигнатура из практики интеграторов |
| `api/v5/supplier/reportDetailByPeriod` — набор полей ответа | то же |
| Поля `sid` и `t` внутри JWT | официальной таблицы полей WB не публикует; при отсутствии поля коннектор пишет `None`, а не догадку |

Битовая маска `s` внутри токена намеренно **не** разбирается: её раскладка
нигде официально не описана, а ошибка в ней означала бы, что коннектор
уверенно сообщает доступ, которого нет. Доступ выясняется у самого API.

## Устройство

```
wbsync/registry.py    единственный список того, куда вообще можно ходить
wbsync/transport.py   HTTP, лимиты, разбор 401/403/429/5xx
wbsync/limits.py      скользящее окно на каждый домен
wbsync/token.py       чтение JWT, срок жизни, диагностика 429
wbsync/cursors.py     курсоры и три способа на них погореть
wbsync/storage.py     SQLite-снимок, атомарная публикация прогона
wbsync/sync.py        сценарии выгрузки
wbsync/cli.py         командная строка
```

Зависимость односторонняя: `cli → sync → transport → registry`. Хранилище
ничего не знает о сети, сеть ничего не знает о хранилище.
